# Pre-registration: the free-form trader (v4), written 2026-10-13 before any run

the trader: "(original wording omitted)". v1-v3 searched a fixed grammar (4 families, daily close). v4 removes that cage and keeps the honesty machinery.

## What the agent may do on its own
- **Data**: hourly bars (server time) built from the MT5 broker M1 data for the same 46 symbols in 4 classes (idx 6, fx 28, cmd 4, crypto 8). Entry at the ask of the bar AFTER the signal bar, exit at the bid close H bars later (short: bid in, ask out), real spread at both ends, flat carry per calendar day as in v3 (0.5 / 0.7 / 1.0 / 3.0 bp). Rows whose exit would fall after the window end are dropped (nothing leaks across DEV/VAL; 2026 is not loaded at all).
- **Features (~26, all causal at bar close)**: vol-normalised returns over 1,2,4,8,24,72,120 bars; RSI 4/14; distance to SMA 24/120/480; vol ratios; relative spread; position in the 24/120-bar range; consecutive-bar run; hour of day; day of week; cross-sectional rank of the 24/120-bar return among the class's markets.
- **Rules it composes**: side (long/short) x holding horizon H in {1,2,4,8,24,48,96} bars x 1-3 conditions `feature >= / <= threshold`, thresholds picked from the class's DEV quantile table (levels 3/10/25/50/75/90/97%; hour 0-21, weekday 0-4). Class is part of the rule. The space is effectively unbounded (> 1e8); every rule ever run counts as a trial.
- **How it searches (its own choice)**: evolutionary: mutate / cross-over its elites, plus fresh random rules; it keeps adaptive operator weights (an exponential moving average of how often each operator beats its parent) and reallocates effort towards what worked. Everything is logged, append-only, outside git (D:\finance\si_ledgers) with a compact summary file committed.

## Test (fixed now)
Stage A (cheap, every rule, DEV 2022-01..2024-12): pooled trades of all the class's markets, mean net return, cluster-robust z (clusters = calendar weeks, so overlapping holds and same-week correlation across markets are absorbed); one-sided normal p. Floors: >= 200 trades, >= 30 weekly clusters, mean >= 3 bp net. S1a = Benjamini-Hochberg q = 0.10 over EVERY rule ever evaluated in the run (cumulative m).
Stage B (only for S1a newcomers): common circular time-shift null (200 shifts of the rule's signal within each market's DEV window, same shift for all markets), z_B >= 3. S1 = S1a and stage B.
S2 (VAL 2025, one look per S1 rule): >= 100 trades, >= 20 clusters, mean >= 3 bp net, one-sided p < 0.20. (Tightened vs v3: the +3 bp floor now applies on VAL too.)
S3 HOLD 2026: never loaded by the agent. Looked at once, only for S2 passes, by me, after a written decision.
S4 against the installed system, tester real ticks, forward: unchanged from PREREG_SELF_IMPROVING.md. A rule that works only on a few symbols is reported with its breadth (share of the class's markets with a positive VAL mean).

## Calibration gate (before the real run)
3 placebo worlds: every hourly return of a class shuffled by ONE common permutation (cross-market correlation kept, all serial and time-of-day structure destroyed), spreads kept; same agent, same settings, 40,000 rules each. Calibrated only if EVERY world has 0 S1 survivors. If not, the test is tightened and the gate repeated, the failed attempt reported.
## Real run
Same code and bars, up to 200,000 rules (checkpointed each generation, resumable), below-normal CPU priority, files on D:.

## Expectations written now
The searched families so far (dip/RSI/breakout, daily) were dead after the winner's curse; a richer, intraday, multi-symbol space has more room but also many more trials, so the cumulative bar is much higher. A positive finding must be a rule that survives stage B, S2 with >= 3 bp and breadth across many symbols; the most likely outcome is again none, with the machine's answer being a calibrated one.

## Amendment 1 (2026-10-13, after calibration attempt 1, before any further run): the first design failed calibration
Attempt 1 (3 placebo worlds, 20 generations x 2,000 rules): 1,143 / 757 / 2,894 'S1 survivors' and 974 / 84 / 289 'S2 passes' in worlds without structure. Diagnosis from the ledger: every false survivor was a long cmd rule at 24-96 bars; the shuffled paths keep the assets' drift, so a long rule earns 30-70 bp in ANY window (DEV and VAL alike) and a 'mean > 0' test is the wrong null; and the search is adaptive (children are drawn from winners), so a cumulative Benjamini-Hochberg over everything evaluated is not valid selective inference (v3 happened to pass only because its space was small). Also, the placebo scaled whole bars by a price ratio, which kept each bar's real open-to-close return (hour-of-day seasonality) inside the first bar of a hold.
Changes, all fixed now:
1. Statistic = EXCESS over random timing: each trade's net return minus the mean net return of the same market, side and horizon over the window (what entering at a random hour would have earned, costs and drift included); cluster-robust z (weekly clusters) on the excess. A trade-level net floor of +3 bp is still required for S1/S2.
2. Exploration / confirmation split: windows A = 2022-01..2023-06 (the agent searches, mutates and selects elites ONLY on A), B = 2023-07..2024-12 (never seen by the search). Promotion A -> B: excess z_A >= 2.5, >= 150 trades, >= 20 clusters, at most the 300 best new rules per generation. Every promoted rule is tested once on B; S1 = Benjamini-Hochberg q=0.10 over ALL B tests ever made (m = number of promoted rules; valid because selection used only A) AND net mean >= 3 bp, >= 100 trades, >= 20 clusters on B. Stage B shift null is dropped as redundant.
3. S2 (VAL 2025): >= 100 trades, >= 20 clusters, net mean >= 3 bp, one-sided p < 0.20 on the excess z. HOLD 2026 sealed as before. Threshold tables (feature quantiles) are computed on A only.
4. Placebo: whole bars are shuffled (gap, open-to-close, open-to-low), one common permutation per class, spreads kept by timestamp; hour-of-day, seasonality and serial structure are all destroyed, drift stays.
5. Calibration gate repeated with the same size (3 worlds x 40,000 rules): calibrated only if EVERY world has 0 S1. If this fails too, the failure is reported before anything else is tried.

## Amendment 2 (2026-10-13, after calibration attempt 2, before the next run)
Attempt 2 (excess-over-random-timing on NET returns, A/B split, whole-bar placebo; 3 worlds x ~27,000 rules): S1 = 2 / 0 / 4, S2 passes 0 / 0 / 0, B tests ~5,600 per world. The gate requires 0 S1, so attempt 2 FAILED, narrowly. Diagnosis from the ledger: the best A z in all three worlds is about 12, and the top 400 rules of world 9 all use `hour` + `sprel` (relative spread), all fx, all H=1, net mean -1.0 bp: they avoid the expensive hours, which saves cost versus random entries. That is cost avoidance, not timing skill, and it is real in the placebo because spreads are kept by timestamp; B z in that world averages 6.8 (it persists across windows). Combined with drift (net >= 3 bp) it let a few rules through.
Change (fixed now): the test statistic is the excess of the GROSS return (mid-to-mid, before spread and carry) over the gross return of random timing for the same market, side, horizon and window; cluster-robust z as before. The net floor (+3 bp per trade on B and VAL) is kept as the economic requirement. Everything else unchanged. Calibration gate repeated (attempt 3), same size. If attempt 3 does not give 0 S1 in all three worlds, it is reported as failed.

## Amendment 3 (2026-10-13, after calibration attempt 3, before attempt 4)
Attempt 3 (gross-excess statistic): world 8: S1 0; world 9: S1 0; world 7: S1 4 and S2 passes 1 (net +56 bp on 177 VAL trades). The gate requires 0 S1 in EVERY world, so attempt 3 FAILED (1 of 3 worlds). Diagnosis: in world 7 the promoted rules' B z has mean +1.93 (worlds 8/9: -0.5 and +0.4) and the 4 survivors are two ideas (three of them the same rule with its conditions in a different order) with z about 4 on 79 weekly clusters. The p-value used the normal tail, but a cluster-robust z with G = 79 clusters is t-distributed with G-1 degrees of freedom (the standard small-G correction), roughly 4x larger p at z = 4.
Change (fixed now): cluster-robust se multiplied by sqrt(G/(G-1)); one-sided p from the Student t with G-1 degrees of freedom (A, B and VAL). Promotion on A stays on the z threshold. Nothing else changes.
Attempt 4 is run on FOUR worlds: seeds 7 (re-run, to see the effect of the fix on the same world) and 10, 11, 12 (new worlds, never looked at); gate = 0 S1 in all four. Disclosure: three looks at calibration so far (attempts 1-3 on seeds 7-9); the fresh seeds guard against tuning to those worlds. If attempt 4 fails, it is reported and the real run does not start.

## Amendment 4 (2026-10-13, after calibration attempt 4, before attempt 5)
Attempt 4 (Student t): S1 = 3 / 0 / 2 / 0 in worlds 7 / 10 / 11 / 12, S2 passes 0 in all four. Gate (0 S1 in every world) FAILED in 2 of 4 worlds. Mean B z of the promoted rules by world: +1.89, +0.89, +2.43, -0.72, so a common component, and in worlds 7 and 11 the top 300 B rules were all fx, short, H = 2-4 bars, and every one used `hour`.
Diagnosis: the 'gross' return was mid-to-mid with the exit-bar spread taken from the OPEN of the exit bar (bc + spread/2). Spreads depend strongly on the hour (rollover), so a rule picking entry/exit hours harvested a spread-timing artifact that persists across windows. Smoke test after the fix (world 11, 8 generations x 2,000): mean B z moved from +2.43 to -1.29 and no rule has a small p.
Changes (fixed now): (1) gross return = bid-to-bid (bc[exit] / bo[entry]), no spread at either end; the net floor (+3 bp) still uses the real bid/ask. (2) BH q = 0.05 (was 0.10): under the global null BH only guarantees P(any rejection) <= q, so at q = 0.10 a perfectly calibrated test would fail 'zero in every world' about 10% per world; the gate was inconsistent with its own nominal level. (3) Attempt 5 = four worlds: 11 (the worst, re-run) and 13, 14, 15 (never looked at); gate = 0 S1 in all four. Disclosure: four attempts so far; if attempt 5 fails it is reported and the real run does not start.

Calibration attempt 5: PASSED. Worlds 11 (re-run), 13, 14, 15 (new): 0 S1 and 0 S2 in every world, 20 generations x ~2,000 rules each (A total 30,700-36,800 rules, 3,000-5,500 B tests per world). Five attempts in total (1-4 failed and are reported above). The real run starts after this entry with the same code (gross = bid-to-bid, Student t, q = 0.05, windows A / B / VAL, 2026 not loaded): up to 100 generations x 2,000 rules (200,000), checkpointed, below-normal priority, ledger D:\finance\si_ledgers\FF5_real.csv.

## Amendment 5 (2026-10-13, after generation 21 of the first real run, before the second): execution realism, no entries in the rollover window
First real run (I looked at it at generation 10 and stopped it at generation 21, 33,400 A rules; ledger kept as FF5_real_run1_rollover.csv): best A z 24 (placebos: 5-8), 8-93 S1 and 1 S2 pass, but the top rules are all the same idea: fx, long, H = 1-2, hour <= 0 (server hour 0 = the hour after the 17:00 New York rollover), often with high relative spread. Measured directly on window B across the 28 pairs: mid-to-mid return of hour-0 bars +2.49 bp (10,874 bars) vs +0.01 bp for all bars; spread at entry 2.2 bp vs 1.1 bp one bar later; net after paying the ask about +0.8 bp per trade (+1.5 to +2.5 bp on 149 VAL trades). A real quote-structure effect of the rollover hour, not an exploitable edge: that window is where fills slip or fail, and the net is below the 3 bp floor in the stable samples. The agent was filling its elites with variants of it (monoculture).
Change (fixed now, an execution-realism rule decided from the known behaviour of rollover liquidity, not tuned on a result): no entry on bars with server hour 23 or 0 (any class). Everything else unchanged (calibration is unaffected: it only removes rules; one placebo world is re-run as a sanity check). The second real run starts afterwards: up to 100 generations x 2,000 rules, ledger FF6_real.csv.

## Amendment 6 (2026-10-13, after the second real run reached generation ~10, before the third)
Second real run (rollover entries forbidden; stopped at generation ~11, ledger kept as FF6_real_run2_zdriven.csv; fresh placebo world 16 with the same code: 0 S1, 0 S2, kept as FF6_placebo16_calcheck): best A z still about 22 and the top 300 A rules are all fx, short, H = 2, `hour >= 7`, mostly with `sprel`, net -1.8 to -4 bp per trade (B z about 23, B net -3.8 bp). The z is huge because the baseline (random timing over ALL bars) still contains the rollover hours that are now forbidden, and with 15,000 trades a tiny gross difference is 'significant'. The net floor (+3 bp) already blocks them (1 S1), but ranking elites by z alone steers the search into rules that lose money, wasting the budget.
Changes (fixed now): (1) the random-timing baseline uses only the bars where entry is allowed (server hours other than 23 and 0), consistent with Amendment 5; (2) search guidance: a rule is promoted to B and may become an elite only if its net mean on window A is >= +1 bp (A only, so the B/VAL tests and their error control are untouched). The test statistics, floors (+3 bp net on B and VAL), BH q = 0.05, windows and the 2026 seal are unchanged.
Sanity check before the third real run: two placebo worlds with the new code (seeds 17 and 18, never looked at), 20 generations x 2,000 rules each, run in parallel with the real run; the real run is only reported if both have 0 S1 and 0 S2. Ledgers FF7_*.

## Run 3 result and audit (2026-10-13, before Amendment 7)
Third real run (rollover entries forbidden, allowed-bars baseline, net-guided search; placebos 17 and 18 with the same code: 0 S1, 0 S2): 100 generations, 103,876 A rules, 15,276 B tests, S1 = 9 rules, S2 passes = 4 (ledger D:\finance\si_ledgers\FF7_real.csv). The S2 passers are two ideas, both fx short with H = 96: R3 (ma480 high, cs120 low, vr24 not low; three copies) and R7 (z24 and z4 spike, short).
Audit written after seeing them (one position per pair, entry on the first signal bar, next entry only after H bars; carry sensitivity 1.5 bp/day instead of 0.7): R3: A +19.4 bp (73 trades), B +4.0 bp (100), VAL -0.6 bp (34 trades on 21 weeks; 414 'test-style' VAL trades were 34 independent entries counted many times) -> falsified. R7: A +17.9 bp (581), B +4.9 bp (546), VAL +12.3 bp (353 trades, 50 weeks, 18 of 28 pairs positive, the winners are the JPY crosses: USDJPY +36, GBPJPY +32, CADJPY +46); with 1.5 bp/day carry: +13.9 / +0.9 / +8.3 bp -> weak and carry-sensitive, not an edge yet. 2026 (HOLD) has not been read.
Lesson: the test counted every signal bar as an independent trade; persistent signals (a condition that stays true for hours) were over-counted and the weekly clustering did not fix the weighting of the mean.

## Amendment 7 (2026-10-13, before the fourth real run): one entry at a time
Change (fixed now): a rule can only enter on bars whose position in its window segment is a multiple of its holding horizon H (entry grid with spacing H, same grid for every market so cross-market clustering is kept). This makes the trades of a market non-overlapping by construction, without path dependence, and cuts the over-counting of persistent signals (power falls roughly by H for the long horizons, which is the honest cost). Used in A, B and VAL, and in the baseline (random timing on the same grid). Everything else unchanged. Calibration sanity: two never-seen placebo worlds (19, 20) run in parallel with the real run; the real run is reported only if both have 0 S1 and 0 S2. Ledgers FF8_*.
