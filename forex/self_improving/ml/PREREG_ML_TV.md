# Pre-registration: ML on raw bars plus relative tick volume (written 2026-10-13, before ml_lab_tv.py ran)
the trader: "(original wording omitted)". The only MT5-native input the ML lab has not seen is tick_volume (M1, data\ticks_vol, server clock like the bars). One extra input channel per 15-minute bar over the same 48-bar window: log(tick volume of the bar / its causal rolling median over 96 bars), clipped to +-3. Everything else is ml_lab.py unchanged (model, cells, floors, rollover exclusion, Bonferroni 0.05/12, VAL once, 2026 sealed). Note the VAL 2025 year has been seen by ML runs and by the reverse test: this run is a screening, a pass would need the sealed hold and a forward test anyway.
Calibration: placebo worlds 91, 92, 93 (shuffled bars carry their tick volume along) must give 0 passing cells each (else <= 1 of 10 by the sequential rule); the real run is read only after that.
Expectation: tick volume is a proxy for activity already captured by realised variance and spread in the existing channels; the most likely outcome is no passing cell.
Implementation note: Stack.shuffle moves the return statistics of a bar (mv columns) and leaves other columns with the timestamp, so tvr stays with its timestamp in the placebo worlds: it carries no information about the shuffled future by construction, which is what the gate needs.
